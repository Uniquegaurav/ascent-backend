# Credentials & Secrets — summit-backend

All backend secrets are **environment variables** — nothing is committed to git.
Set them in the **Render dashboard** (service → Environment) for production, or
in the local `.env` file (git-ignored, copy from `.env.example`) for dev.

## Production (Render dashboard)

| Variable | Status | Where to get it | Notes |
|---|---|---|---|
| `JWT_SECRET` | ✅ auto-generated by Render | — | Don't touch. Rotating it signs everyone out. |
| `DATABASE_URL` | ✅ auto-wired by Render | — | From the `ascent-db` Postgres. |
| `ENV` | ✅ set to `prod` via render.yaml | — | Anything except `dev` enforces prod safety rules. |
| `SMS_PROVIDER` | ⬜ `log` for now | switch to `msg91` once the two keys below are set | With `log`, OTP codes only appear in Render logs — real users cannot sign in. |
| `MSG91_AUTH_KEY` | ⬜ **PASTE HERE (Render env)** | msg91.com → Authkey | Needed for real OTP SMS. |
| `MSG91_TEMPLATE_ID` | ⬜ **PASTE HERE (Render env)** | MSG91 → OTP template (DLT-approved, must contain `##OTP##`) | India DLT registration required for sender ID. |
| `OTP_REVIEW_PHONE` | ⬜ **PASTE HERE (Render env)** | your own phone in E.164, e.g. `+91XXXXXXXXXX` | The fixed code below works ONLY for this number in prod (your demo login + app-store review). |
| `OTP_DEV_CODE` | ⬜ e.g. `111111` | pick any 6 digits | Ignored (auto-disabled, warning logged) unless `OTP_REVIEW_PHONE` is also set. |
| `GOOGLE_PLACES_KEY` | ⬜ **PASTE HERE (Render env)** | Google Cloud Console → enable Places API (legacy) + Geocoding API | Without it the explore feed uses the built-in sample catalog. Responses are cached server-side (6–24h) to keep spend low. |

## Local dev (`.env`, git-ignored)

Copy `.env.example` → `.env`. Defaults work out of the box:
`ENV=dev`, `SMS_PROVIDER=log` (codes print to stdout), `OTP_DEV_CODE=000000`
always verifies in dev.

## Deploying

Render auto-deploys the `main` branch of this repo. Migrations run
automatically on boot (`internal/db/migrations/`). Keep the service at
**1 instance** (migrations have no cross-instance locking yet).

Post-deploy check:
```sh
curl -sD- https://ascent-api-rzft.onrender.com/health
# expect: 200 {"status":"ok"} and an X-Request-Id header (proves the new build)
```
